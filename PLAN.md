## 2. What we are building

**Concept: one continuous world, scrolled.** A single live Three.js scene the visitor
travels through, where each chapter is a place in that world rather than a stacked
section on a page. Scroll is the conductor. The pointer is a live input, not decoration.

**Narrative spine: Dhaka to Calgary, and what got built along the way.** This is the
thread the old site misses entirely. Adnan is a Bangladeshi citizen studying CS in
Calgary who runs a Calgary business and builds the software for a Dhaka factory. Two
continents, real work on both. That is the story no template gives you.

**Positioning, in one line:** a CS student who ships production systems for two real
businesses on two continents.

Every claim traces to something verifiable. No aspiration presented as fact.

## 3. Chapters

Six stops, all scenes in one persistent Three.js scene graph, not separate canvases.

1. **Arrival.** Name, one true claim, the world establishing itself.
2. **Ground.** Calgary. CS at the University of Calgary. Where he is now.
3. **TotalTex Ops.** Flagship, deepest chapter. Order to job card to proforma invoice to
   production to delivery challan to bill, for a real Dhaka factory.
4. **Puzzled.** The Calgary business he runs and wrote the automation for.
5. **Field notes.** TotalTex Web (live, linkable), FitTrack (live, playable), and the
   working system behind all of it.
6. **Contact.** The globe finale. See section 6.

## 4. Technical decisions, made

### 4.1 Live Three.js, not pre-rendered video

The `scroll-world` skill (installed at `~/.claude/skills/scroll-world`, MIT, 8.9k stars)
generates a fly-through by rendering AI video clips and scrubbing them by scroll. Its
asset pipeline requires **Monid at roughly $27 per 6-scene chain, or Higgsfield credits**.
Both are banned for this build.

Its `references/scrub-engine.js` is genuinely good and dependency-free, but it only
consumes pre-rendered MP4s. That route means building a render farm to produce footage
that is then dead to the cursor.

**Decision: one live Three.js world via `build-threejs-scroll-worlds`.** Zero render
pipeline, zero dollars, responds to the pointer, and the globe becomes a scene in the
same renderer instead of a second WebGL context fighting the first.

**What we keep from scroll-world:** the choreography model. Its per-section `scroll`
(dwell distance) and `linger` (time remapping so the camera settles where the copy peaks)
are the right pacing vocabulary, and its seam discipline (never cut, always connect) is
what makes a scroll world feel like one place. Ported as a spec, not as code.

**Escape hatch:** if one scene proves too heavy for mobile, that scene alone falls back to
a pre-rendered clip through the scrub engine. The engine stays available. It is not the
foundation.

### 4.2 Globe: cobe, not globe.gl

Measured via bundlephobia:

| Package | Raw | Gzip |
|---|---|---|
| **cobe** | 13,004 B | **5,931 B** |
| globe.gl | 2,002,975 B | 559,272 B |

globe.gl is 94x larger gzipped and drags in three-globe, d3-array, d3-color, d3-geo,
d3-scale, d3-scale-chromatic, h3-js, tinycolor2 and kapsule. cobe has **zero runtime
dependencies** and imports as plain ESM. No CDN, no key.

`cobe@2.0.1` natively supports arcs (`from`, `to`, `arcColor`, `arcWidth`, `arcHeight`),
verified against the live package README. **The installed `cobejs` SKILL.md is out of date
and documents markers only.** Verify options against the live package at build time.

Known gap: cobe has no built-in progressive arc draw-in. A scroll-driven "arc drawing
itself" effect must be hand-animated by driving arc opacity and count from scroll progress
inside the `onRender(state)` callback. Budget a build task for it.

Rejected: `globe-particles` (no lat/lon projection or arc primitive, decorative only),
`unicorn-studio` (paid SaaS, scenes hosted on their cloud, SDK from jsDelivr),
`vantajs` (loads three.min.js and effects from CDN, and has no globe effect at all).

### 4.3 Stack

Next.js 16 + React 19 + TypeScript + Tailwind 4. Same as the old repo (already current)
and the same as `totaltex-web`, which is proven in production.

### 4.4 Reuse before writing (ponytail rung 2)

`totaltex-web` already contains battle-tested, accessibility-hardened primitives Adnan
owns outright. Copy these rather than reinventing:

| File | What it gives us |
|---|---|
| `lib/motion.ts` | One site-wide easing constant, `cubic-bezier(0.16, 1, 0.3, 1)` |
| `lib/scroll.ts` | Lenis-first smooth-scroll-to-id with reduced-motion fallback |
| `lib/magnetic.ts` | Magnetic pull with documented damping (about 0.9, no overshoot) |
| `components/reveal.tsx` | Dual-path reveal: CSS `animation-timeline: view()` where supported, IntersectionObserver fallback, plus an `immediate` escape hatch for above-the-fold content (fixes a real opacity-stuck bug) |
| `components/smooth-scroll.tsx` | Lenis + GSAP ScrollTrigger via dynamic import, zero pre-hydration bundle cost |
| `components/story/word-reveal.tsx` | Word-by-word reveal preserving inline semantics |
| `components/home/marquee-pause.tsx` | WCAG 2.2.2 compliant pause control |
| `components/home/thread-divider.tsx` | SVG path morph on scroll via GSAP `attr` tweening, avoids the paid MorphSVG plugin |

Do **not** copy `totaltex-web/app/globals.css` tokens. That warm-paper palette is
TotalTex's client-locked brand. This site needs its own.

### 4.5 Contact backend: Web3Forms

Free tier, no dashboard needed to receive mail, pure client-side POST, delivers to Adnan's
inbox. `mailto:` stays as the accessible fallback link.

Rejected: the FitTrack Cloudflare Worker. It is a Web Push server (VAPID signing, RFC 8291
payload encryption, KV storage), not a form handler, and deploying anything to Cloudflare
is blocked on an interactive `npx wrangler login` that has not happened.

### 4.6 Deploy

Build here, then push to the existing `addyrallxx-site` repo so the Vercel project and URL
carry over. Preserve the old code on a branch before replacing it.

## 5. Content, with evidence

Verified on disk or in the vault. Line counts are `wc -l` excluding `node_modules`.

### 5.1 TotalTex Ops, the flagship

**95 source files, 12,501 lines.** Next.js 16.2.12, React 19.2.4, TypeScript strict,
Drizzle ORM 0.45.2 + Postgres, bcryptjs, jose. 27 commits, 2026-07-28 to 2026-08-31.
Runs against local Postgres, no public URL.

Adnan asked to present this as universal and niche-directed ops software. The honest
version of that pitch is strong on its own, so make it honestly:

**Domain-agnostic modules** (would work for any ops business): auth and roles, the
append-only `audit_log`, the numbering scheme (sequential identity with a manual-override
escape hatch), the snapshot-on-issue pattern, and the order to delivery to bill spine.

**Textile-specific:** the per-product-line spec templates, and the Bangladesh compliance
fields (Mushak reference, deemed-export flag, UD/UP reference).

**The defensible engineering, which is the actual case study:**

- `lib/spec-templates.ts` (186 lines). A typed field-template system where one template
  drives both form generation and the printed description string. `docs/PLAN.md` section 4
  argues this beats ERPNext Item Variants and Odoo Studio, citing frappe/erpnext issues
  #34824 and #13401. This is the strongest "why not a generic ERP" argument and the best
  flagship hook.
- 11-table schema with reasoning inline: `numeric` not float for all money and quantity,
  snapshot-not-join for challan and bill lines, computed not stored job status, `job_no`
  starting at 10000 so any number provably came from the software.
- Real security, not boilerplate auth: bcrypt cost 12, a dummy-hash constant-time compare
  closing the account-existence timing oracle, per-account lockout (10 attempts per 15
  minutes, deliberately not per-IP because the office shares one NAT), server-rechecked
  permissions on every request rather than trusting the token, and a per-request CSP nonce.
- A real bug caught and fixed: `updateJob` used delete-and-reinsert on job lines, silently
  erasing recorded production through a cascading foreign key, because the edit form never
  submitted `job_item.id`. Fixed with a diff-based update (`lib/jobs-diff.ts`) and the key
  changed to RESTRICT as a backstop. This is the single best story on the site: a data-loss
  bug found by reading your own schema.
- 21 runnable assertions across four check scripts, used as a CI substitute.

**Do not claim** that entry beats paper on a stopwatch. The repo's own CLAUDE.md says that
claim "leans passed, and it is still not proven." It was reasoned from source, never timed.
Leaving it off costs nothing and keeps every other claim credible.

**Also do not claim** completeness: 9 of 11 spec templates are unbuilt, daily production
entry is flagged not built, and Tally integration is design-only with no code. Present what
runs.

### 5.2 Puzzled

**7,313 lines of Python.** Runs on a three-times-a-day Windows scheduled task against a
real business Adnan co-founded and operates the technical half of.

- A `curl_cffi` scraper defeating TLS fingerprinting across three dealer platforms
  (Convertus VMS, LeadBox HQ, DealerEProcess), including gallery photo extraction.
- A rule-driven description generator that only states facts present in the scraped record,
  auto-selects a sales angle, and applies jurisdiction-specific legal disclaimers.
  287 of 335 descriptions generated at zero API cost.
- A compliance audit of 1,069 real descriptions against AMVIC advertising regulation, which
  surfaced two live violations that predated Puzzled.
- A real production incident found and fixed: a caching bug meant 58 vehicles were no longer
  live and 38 price changes were missed.

The regulated-industry angle is the interesting part: constrained generation where being
wrong is a legal problem, not a UX problem.

### 5.3 TotalTex Web

**83 files, 11,506 lines, 383 real production images.** Live at `totaltex-bd.com` since
2026-08-01, custom domain, zero-downtime DNS cutover. Next.js 15.5, React Three Fiber,
GSAP, Lenis, Nodemailer.

Best sub-story: `components/structured-data.tsx` was emitting `"@type": "Factory"`, which

This is the only project with a live, clickable, third-party-verifiable URL. Lead the work
chapter with it for that reason.

### 5.4 FitTrack

Live and installable at `addyrallxx.github.io/fittrack/fittrack.html`, public repo.

Value on the site: it is the one thing a visitor can open and use in five seconds.

## 6. Contact: the globe finale

Adnan asked for the contact section to be interactive, immersive and tied to the scroll
motion, and for Calgary, Bangladeshi citizenship and worldwide reach to be prominent.

**The cliche to avoid:** a decorative spinning Earth in a dark hero is the most overused
pattern in this genre. We are not doing that.

**What we do instead.** The globe is the contact chapter's instrument and it runs on real
data. As the visitor scrolls into the final chapter, the globe rotates under scroll control
from Dhaka to Calgary. Small, precise, monochrome against one signal color.

Three layers, in order of appearance:

1. **Origin.** Dhaka, Bangladesh (23.8103 N, 90.4125 E). Bangladeshi citizen.
2. **Present.** Calgary, Alberta (51.0447 N, 114.0719 W). Studying CS at the University of
   Calgary. The emphasised node, per Adnan's instruction.
3. **Reach.** The one real documented personal route is the annual May to August Calgary to
   Dhaka corridor, flown via Doha or Istanbul because no direct route exists. Draw that as
   an actual route. The wider international layer is the family business's buyer network
   across 54 apparel brands (Sweden, Spain, US, Hong Kong, Turkey, Poland), which must be
   labelled as **TotalTex's supply-chain reach, not Adnan's personal travel.**

That framing distinction is not pedantry. Claiming personal global reach he does not have
is exactly the kind of unearned claim the old site died of.

**Interaction, all zero-dependency:**

- Hovering a contact method lifts its node on the globe. Hovering a node highlights the method.
- Magnetic pull on the primary call to action. About 15 to 20 lines of vanilla JS, no
  library. No magnetic-button skill exists on this machine and none is needed.
- A live "it is currently HH:MM in Calgary" clock, computed client-side.
- Copy-to-clipboard with inline confirmation on email.

**Accessibility floor, non-negotiable:** every hover effect has a non-hover equivalent,
every globe node is a real focusable element with an accessible name,
`prefers-reduced-motion` renders a complete static composition rather than a blank one, and
the globe is `aria-hidden` with the same information available as text.

## 8. Copy system

**Hard rule: no em dashes anywhere.** Periods, commas, colons, parentheses. The old site
breaks this in its own hero.

**Voice, three rules:**

1. State what was built or done, never what kind of person he is. Never open with an
   identity label. Open with a verb and an object.
2. One claim, one fact behind it. Every line traces to something on disk or in the vault.
3. Short declarative sentences, 8 to 14 words. Where the old copy reached for an em dash,
   use a period and a new sentence, or a colon when the second half explains the first.

**Banned outright:** "Builder.", "Operator.", "Always in motion", "one project at a time",
"systems thinking" as self-description, "real value for real people", "I think like an
operator first and an engineer second", "Built from scratch", "Designed with intent",
rule-of-three list saturation, and numbered section kickers.

**Also cut:** unverifiable skill claims. The old site claims Solana, DeFi, Phantom, BTC and
Security with nothing shipped behind any of them. If it has no artifact, it is not on the site.

**Hero direction, leading candidate.** Ground it in the two-continent fact, since that is
both true and unusual:

> Headline: I build the software two businesses actually run on.
>
> Subhead: Order management for a Dhaka factory. Listing automation for four Calgary
> dealerships. Computer science at the University of Calgary.

Run every final line through `/humanizer` before it ships.

### Parallel agent rules for this project

Per machine CLAUDE.md, learned the hard way:

- Partition agents by **file ownership**. Name in every brief the files that agent owns and
  the files another agent is holding.
- **Pin the interface before starting.** Exact function signature, exact payload shape. File
  ownership stops overwrites, it does not stop interface drift.
- **Forbid `git stash` in every brief.** Use `git diff` to inspect.
- Pass `model: 'sonnet'` and `effort` on **every** fan-out agent. A Workflow `agent()` call
  silently inherits Opus otherwise.
- Serialise anything that builds or measures. Parallelise anything that only reads and writes
  source.

## 10. Verification protocol

**The Browser pane cannot verify this site.** Automation browsers on this machine report
`document.hidden = true`, which throttles `requestAnimationFrame`, so Three.js motion, GSAP
and the cobe globe never visibly run there, and `loading="lazy"` images come back
`naturalWidth: 0` with zero network requests. That looks exactly like a broken build.

**Drive real Chrome with `puppeteer-core`** for every motion check. `puppeteer-core` is
already installed in `totaltex-web` and `totaltex-ops`, so the pattern is proven here.
Chrome is at `C:\Program Files\Google\Chrome\Application\chrome.exe`.

Prefer asserting numerically (`getBoundingClientRect`, `getComputedStyle`) over looking.
Screenshots cost roughly 3,600 tokens each at 2160px: shoot at `deviceScaleFactor: 1`, crop
to the element, resize to 1000px or less, read one confirming frame.

**A run completing is not a task succeeding.** Read `journal.jsonl` for actual per-agent
return values, then re-run the claim independently.
